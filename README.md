# Stillum — Корпоративная медиа-платформа и CMS для независимого музыкального лейбла

Проектирование и реализация специализированной системы управления контентом (CMS) с бесшовным медиастримингом и инструментами прямого взаимодействия с аудиторией (D2C).

---

## 📌 Бизнес-контекст и проблематика (AS-IS)

Музыкальный лейбл столкнулся с ограничениями существующих каналов дистрибуции:
* **Зависимость от стриминговых монополистов:** платформы (VK, Яндекс.Музыка, Spotify) забирают значительную долю выручки, закрывают прямой доступ к аналитике аудитории и не дают выстраивать прямое общение «артист-фанат».
* **Непригодность коробочных CMS (WordPress, 1C-Bitrix):** архитектура многостраничных приложений (MPA) приводит к прерыванию аудиопотока при любом переходе по сайту.
* **Высокая стоимость кастомизации:** переделка классических решений под задачи бесшовного стриминга (создание Headless-архитектуры) превышала бюджет в 1.9 млн руб.

---

## 🎯 Цели и задачи системного анализа (TO-BE)

* Провести предпроектное обследование и формализовать требования к узкоспециализированной CMS лейбла.
* Спроектировать реляционную модель данных (3NF) с оптимизацией под транзакционную консистентность и социальные механики.
* Разработать ролевую модель доступа (RBAC).
* Сформировать архитектурный ландшафт, исключающий разрыв медиапотока при навигации.
* Рассчитать совокупную стоимость владения (TCO), капитальные (CAPEX) и операционные затраты (OPEX).

---

## 👥 Ролевая модель доступа (RBAC)

Система поддерживает гранулярное разделение прав:

* **Слушатель (FREE):**
  * Потоковое воспроизведение общедоступного аудиоконтента.
  * Социальное взаимодействие: добавление треков в избранное, публикация комментариев, реакции эмодзи.
  * Формирование персональных плейлистов.

* **Премиум-слушатель (PLUS):**
  * Доступ к стримингу в формате высокого разрешения (Lossless).
  * Расширенная кастомизация профиля (фоновые обложки, индивидуальные бейджи).
  * Эксклюзивный доступ к закрытым релизам лейбла.

* **Артист / Менеджер лейбла (ARTIST):**
  * Загрузка релизов и управление метаданными (названия, жанры, обложки).
  * Модерация комментариев и установка статуса «Понравилось автору».
  * Мониторинг продуктовой аналитики (прослушивания, прирост подписчиков).
  * Деструктивные действия с подтверждением через модальные сценарии (AlertDialog).

## 🛠 Технологический стек и архитектурные решения

* **Архитектурный паттерн:** Single Page Application (SPA) на базе фреймворка Next.js для исключения полной перезагрузки страниц и сохранения непрерывного медиасеанса.
* **Клиентский слой:** React, стейт-менеджер Zustand (полная изоляция состояния плеера от дерева маршрутизации), Optimistic UI (визуальный отклик интерфейса за 0 мс с автоматическим механизмом отката при ошибке).
* **Серверная логика:** Next.js Server Actions (RPC-подход вместо классического REST API; устранение избыточного бойлерплейт-кода и обеспечение сквозной типизации данных).
* **База данных:** PostgreSQL, нормализация до уровня 3NF.
* **Слой доступа к данным:** Prisma ORM (строгая валидация схем и управление внешними ключами).
* **Хранилище медиа:** объектное облачное S3-хранилище (медиафайлы изолированы от базы данных и раздаются напрямую через Presigned URLs для разгрузки сервера).

## 🗄 Модель данных (ERD-сущности)

База данных спроектирована в третьей нормальной форме (3NF) с каскадным удалением зависимостей (Cascade Delete) и составными ключами для оптимизации связей M:N:

* **User:** идентификатор (`UUID PK`), почта, пароль, имя, роль (`FREE` / `PLUS` / `ARTIST`), дата создания.
* **Track:** метаданные композиции (`UUID PK`), название, длительность, жанр, ссылки на S3 (`audio_url`, `cover_url`), внешний ключ `artistId` (`User.id`).
* **Playlist:** списки воспроизведения (`UUID PK`), наименование, внешний ключ `userId` (`User.id`).
* **Comment:** комментарии к трекам (`UUID PK`), текст, связи `userId` и `trackId`.
* **Reaction:** реакции на комментарии с составным ключом `(commentId, userId, emoji)`.
* **TrackLike / PlaylistLike:** фиксация пользовательских лайков через составные первичные ключи `(userId, targetId)`.
* **Follows:** социальный граф подписок через составной ключ `(followerId, followingId)`.
* **Notification:** системные события; для обеспечения гибкости структуры полезной нагрузки используется тип данных `JSONB` (`payload`).

В рамках аналитического этапа было проведено технико-экономическое обоснование собственной разработки в сравнении с внедрением 1С-Битрикс: Enterprise:

| Параметр | Кастомная разработка Stillum | 1C-Битрикс: Enterprise + доработка |
| :--- | :--- | :--- |
| **Лицензионные отчисления** | **0 руб.** (Open Source ядро) | 400 000 руб. (базовая лицензия) |
| **Затраты на интеграцию/кастомизацию** | 777 152 руб. (MVP под ключ) | ~1 500 000 руб. (переделка под Headless) |
| **Итоговая стоимость создания (CAPEX)** | **~777 тыс. руб.** | **~1,9 млн руб.** |
| **Ежемесячный OPEX (хостинг, S3, поддержка)** | **~30 000 руб./мес.** | ~60 000 руб./мес. |
| **Срок окупаемости проекта** | **~8,5 месяцев** | ~21 месяц |

### Ключевые результаты для бизнеса:
1. **Экономия бюджета:** затраты на запуск платформы снижены более чем в 2 раза по сравнению с адаптацией коробочных систем.
2. **Цифровой суверенитет:** 100% владение исходным кодом, базами данных и отсутствие лицензионных рисков.
3. **Прямая монетизация:** окупаемость за 8.5 месяцев за счет внедрения подписочной модели PLUS и продажи B2B-лицензий другим независимым лейблам.
